# 登录、最高分和上线准备

## 当前已经接入

项目现在由一个 Node.js 小服务器同时提供网页和接口：

- `POST /api/login`：四个固定账号登录。
- `GET /api/me`：确认当前登录状态。
- `POST /api/scores`：提交本局分数，只更新个人最高分。
- `GET /api/leaderboard`：按最高分从高到低返回四位玩家。
- `GET /api/health`：检查服务器是否正常。

这是公开试玩版，登录区会明确显示每个昵称对应的密码，方便孩子直接进入。服务器仍然只在 `data/accounts.json` 中保存密码哈希和最高分数据；这个文件已经加入忽略列表，不会被提交到代码仓库。

## 本地测试

在项目目录执行：

```bash
npm start
```

然后访问：`http://127.0.0.1:8001/index.html`

## 数据保存说明

最高分保存于服务器的 `data/accounts.json`，不是浏览器 `localStorage`。因此四个孩子只要访问同一个线上地址，就能看到同一份排行榜。

正式部署时必须给 `/app/data` 配置持久化磁盘或等效持久化数据库。若托管平台重启后不保留这个目录，排行榜会丢失。

## 已准备的部署文件

- `package.json`：无第三方依赖的启动配置。
- `Dockerfile`：可部署到支持 Docker 的 Node.js 主机。
- `.dockerignore`：避免把本地运行数据和 Git 信息打进镜像。
- `GET /api/health`：可作为托管平台健康检查地址。
- `GAME_DATA_DIR`：可把账号和分数目录切换到托管平台的持久化磁盘。

## 域名能不能单独完成上线

不能只靠域名完成。域名和 HTTPS 证书解决的是“别人通过什么地址访问”和“连接如何加密”；登录接口和排行榜还需要一台持续运行的服务器或云端函数，以及保存分数的数据库/持久化磁盘。

你至少还需要具备下面两项中的一种：

1. 已经存在的服务器、虚拟主机或支持 Node.js/Docker 的托管空间。
2. 一个可以创建云端项目的托管账号，并允许把你的域名指向它。

如果只有域名、没有 DNS 管理权限或托管空间，我无法在不增加外部授权的情况下把共享排行榜发布出去。

## 上线前仍需要大人确认的事项

- 四个最终昵称和密码。
- 域名的 DNS 管理入口，至少能添加 CNAME 或 A 记录。
- 选择一台能长期运行后端并保存 `data` 的托管环境。
- 确认 HTTPS 是由托管平台、反向代理还是现有主机负责。
- 用手机和孩子实际使用的网络测试访问速度和登录。

孩子们的最终角色图片和技能规则确定后，只需要替换帮手配置并接入技能函数，不需要重新设计登录和排行榜接口。

## 托管方案的现实边界

### 候选一：Cloudflare Workers + D1

这是目前最符合“尽量免费、无需自己维护服务器”的方向：网页和接口可以放在 Workers，排行榜放在 D1。它仍然需要一个 Cloudflare 账号、一次部署，以及域名 DNS 配置；不是只提供域名就会自动完成。

### 候选二：Render 免费 Web Service

可以运行当前 Docker/Node.js 版本，但免费服务会在空闲后休眠，唤醒可能需要等待；免费服务的本地文件也不持久，不能直接用 `data/accounts.json` 保存长期排行榜。免费数据库还有期限限制，因此不适合作为本项目的长期排行榜方案。

### 候选三：GitHub Pages

适合只发布 HTML、CSS、JavaScript 的静态试玩版，但不能单独承载当前登录接口和共享排行榜。

因此，目前能做到的上线预处理已经完成；真正发布前仍必须由大人提供托管账号授权，或已有服务器的连接信息，以及域名 DNS 管理权限。
