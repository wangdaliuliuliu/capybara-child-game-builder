# 当前游戏实现契约

本文件是给执行改动的智能体看的项目边界，不是新的游戏设计。若用户明确提出新规则，先说明它会
改变哪些契约，再按用户确认后的规则实施。

## 项目识别

- 项目：`capybara-bubble-tea-catcher`
- 入口：`index.html`
- 游戏逻辑和助手数据：`script.js`
- 样式和动画：`style.css`
- 登录、排行榜和本地服务：`server.js`
- 角色素材：`assets/`
- 运行时数据：`data/`，不要提交真实账号数据或服务器凭据

## 助手与召唤

- 助手数据集中在 `script.js` 的 `HELPERS` 数组。
- 助手 ID 使用 `helper-1` 到 `helper-4`，账号位、显示顺序和召唤顺序保持稳定。
- 当前召唤值达到 200 才能召唤；达到阈值后不溢出累积，召唤按顺序消耗。
- 助手生命周期是：`entering` → `entered` → `casting` → `exiting`。
- 用现有的 `createHelperElement`、召唤流程和 `startHelperEffect()` 扩展，不要复制另一套
  游戏循环或碰撞循环。

## 动作硬约束

- 进场动画总时长不超过 2 秒，并且必须完整到达施法位置。
- 进场阶段全局暂停下落、碰撞和会改变分数/血量的游戏更新。
- 进场结束进入施法后解除暂停；施法、特效和离场的具体时长按角色设计决定，但应可观察、可结束。
- 动画元素不能遮挡手机上的左右移动按钮、召唤按钮、分数和血量信息。

## 效果实现原则

每个技能实现前写清以下五项：

```text
trigger：什么事件触发
target：作用于谁/什么
change：实际改变
duration：持续多久
reset：结束后如何恢复
```

一次性清场、短时加速、生成一个奖励道具、短时让扣分道具无害等，都必须在效果结束时清理状态。
不得因为视觉类名、粒子或光环而额外修改分数和血量。

## 素材约束

- 角色素材优先为透明 RGBA PNG，建议约 512×512，主体完整，边缘不带整块白底。
- 不覆盖孩子原图，不把原图文件名中的姓名带入公开资源名。
- 浏览器请求素材应返回正确的 `Content-Type`，本地和线上路径都要实际检查。

## 最小验收

```text
node --check script.js
node --check server.js
本地服务可启动
登录昵称/密码与配置一致
角色图片成功加载
一次正常召唤完成完整生命周期
进场 <= 2 秒且进场期间游戏暂停
移动端按钮和 HUD 可用
技能结束后状态恢复
```

线上发布不是本契约的默认步骤。只有收到明确上线授权才备份、部署、重启游戏服务并检查同服务器的
其他站点。
